# Матричный поиск и воспроизводимое сравнение

Дата: 2026-09-07. Основание: пользователь попросил закрепить проверенный матричный алгоритм в собственном проекте, добавить 45 замков в проверки и бенчмарки, формировать доказательный отчёт, после этого готовить перенос в UnlockMyLoot. Отдельный сайт в эту работу не входит.

Эта спецификация обновляет пункты о размере, алгоритме, критерии равенства и наборе данных спецификации 1.0. Остальные правила механики и формат команд сохраняются.

## Контракт

- ES modules, Node.js 20+ для CLI и проверок, без сторонних runtime-зависимостей.
- Вычислительные модули не используют Node.js API, DOM, файловую систему или сеть. Они пригодны для импорта в браузер и Worker.
- По уточнению пользователя добавляется готовый classic-script файл для подключения через обычный `<script>` без npm, CDN и сборки у принимающего проекта. Наш скрипт воспроизводит его из разрешённых ESM-модулей и проверяет синхронизацию с исходниками.
- Модель принимает N>=2, квадратные направленные связи {-1,0,1}, нулевую диагональ, целые позиции 1..7, цель 4. Разреженные JS-массивы некорректны. Предел UI 8 не является правилом механики.
- Каждая команда с steps=1..6 стоит одно действие; зависимости применяются один раз, без каскадирования; полностью заблокированная команда не меняет состояние.
- `solveLock(definition, options?)` сохраняет прежние структуры результата solved/unsolvable. Новый параметр `options.algorithm` принимает `matrix-astar` (по умолчанию) либо `bfs`.
- `matrix-astar` использует точную рациональную алгебру, достаточный сертификат допустимого порядка и A* с согласованной эвристикой sum ceil(abs(r_i)/6). Для вырожденной матрицы применяется точный BFS по действиям.
- Главная гарантия — минимальное количество действий. Выбор равных решений детерминирован. Для режима BFS прежний лексикографический порядок команд сохраняется; у матричного режима порядок может отличаться. Минимум разных пластин и сдвигов не заявляется общей гарантией этой версии.
- Ограничения вычисления задаются отдельно от модели: проверяемое безопасное кодирование, бюджет посещённых и раскрытых состояний, бюджет плотной памяти. `SearchLimitError` означает исчерпание ресурсов, никогда не `unsolvable`. CLI показывает обычную русскую ошибку с кодом 1. Бюджет должен действовать также в BFS fallback; не хранить неограниченно старые узлы heap.
- Небольшой пример README и публичный формат команд (plate с 1, left=+1, steps) сохраняются.

## Проверки

45 именованных входов импортируются из UnlockMyLoot commit eee0bf50ebcb7fffd2b47954fd76bb015854e365. В каждом сохраняются источник, код, начальные позиции, матрица, ожидаемый минимум действий и исходные показатели стороннего решения. Это данные конкретных конфигураций, не автоматическое распознавание игрового состояния.

Каждое найденное решение проверяется независимым симулятором по одному делению. Все 45 сравниваются с точным BFS, а маленькие модели — с независимым полным поиском. Отдельно проверяются дробное/несовместное матричное решение, тупик при существующем целочисленном балансе, необходимость повторного выбора пластины, вырожденность, N=8, ресурсные пределы, детерминированность.

Проверка браузерной совместимости загружает настоящее ESM-ядро без Node.js globals и решает известные входы. Не создаётся продуктовый интерфейс или сайт.

## Бенчмарк и отчёт

Один запуск выполняет прогрев и повторные измерения на всех 45 входах, проверяет корректность и минимум действий, создаёт JSON и Markdown отчёт. Сравниваются текущий матричный режим, BFS и закреплённая исходная версия нашего BFS. Дополнительный аргумент пути к отдельно клонированному UnlockMyLoot включает измерение его неизменённой функции на том же runtime; SHA/хэш подтверждается, чужой код в Apache-репозиторий не включается.

Отчёт содержит версии исходников, хэш данных/ядра, среду, параметры запуска, единицы миллисекунд, по каждому замку A/U/C и время min/median/max, сводку выигрышей/ничьих, ограничения выводов. Исторические метрики конкурента явно отделены от текущих измерений, если checkout не предоставлен.

Корректность и оптимальность — обязательные gates. Абсолютное время и коэффициент ускорения — измеряемые результаты; нестабильные пороги времени не входят в обычные unit tests. Бенчмарк не утверждает ускорение, если измерения его не показали.

## Результат

Код, fixtures, проверки, сценарии и сформированный отчёт сохраняются в нашем Git-репозитории. Затем готовятся два альтернативных upstream draft PR: дополнение в стиле существующего кода и подключение отдельного готового файла. Оба сохраняют исходный режим и дают необязательный минимум действий. Точные описания с воспроизводимыми результатами согласуются с пользователем перед открытием PR. Публикация собственного сайта не требуется.
