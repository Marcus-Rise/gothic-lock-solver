# TypeScript-библиотека Gothic Lock Solver

Статус: **черновик для согласования, реализация не начата**.
Дата: 2026-09-07. Текущая задача ограничена нашим репозиторием.

## Цель и границы

Превратить проверенный решатель в читаемую, типизированную и воспроизводимо
публикуемую библиотеку. Потребитель подключает один готовый файл и получает
последовательность открытия замка по состоянию и связям.

Референс сохраняется в `feat/matrix-astar-benchmarks`, commit
`3cbbeedbb409a2d8ffa5b00c778cfcb0b07c0ec6`. Код бенчмарка выполнен на доступном
commit `6b1cfbc13bcec68f609d45d5dc97504dd84f1760`; результаты находятся в
`docs/benchmarks/run-20260907T070258001Z-f78dff13`.

Новая ветка `feat/typescript-core-library` начинается от референса. Её PR сначала
направляется в референсную ветку, чтобы показывать только преобразование библиотеки.
Слияние в `main`, активация публикации и сторонние PR в этот этап не входят.
Workflow публикации будет подготовлен и проверен; боевой выпуск запускается после
будущего одобренного слияния в `main`. Собственный сайт и UI не создаются.

## Публичный контракт — предложение для утверждения

```ts
type Command = Readonly<{
  plate: number;
  direction: 'left' | 'right';
  steps: number;
}>;

function solveLock(
  state: readonly number[],
  links: readonly (readonly number[])[],
): readonly Command[] | null;
```

Ровно два аргумента. N выводится из `state.length`; отдельные N, цель, алгоритм,
бюджеты, callbacks и настройки в публичный вызов не добавляются. Внешнее API
не возвращает телеметрию или оболочку с копиями входа. Типы диапазонов могут быть
уточнены при реализации без изменения формата данных JavaScript.

**Предлагаемое представление состояния:** вектор позиций `[1,7,4,…]`, по одному
значению на пластину. Каждая строка визуального поля N×7 описывается одним числом.
Смысл этого выбора нужно подтвердить с пользователем перед реализацией: запрос
использует выражение «матрица состояния», а текущая модель хранит вектор.

- Модель допускает N≥2; позиции — целые 1…7, цель — все 4.
- `links` имеет размер N×N, значения −1/0/1, диагональ 0.
- `links[source][target]` задаёт прямое направленное влияние без каскада.
- `plate` в командах начинается с 1; `steps` — целое 1…6.
- Сохраняется текущая координатная конвенция: `left` увеличивает позицию,
  `right` уменьшает. Потребитель отвечает за соответствующее отображение в UI.
- Каждая команда и её промежуточные деления допустимы; входы не изменяются.
- `[]` означает уже открытый замок; `null` — доказанную недостижимость цели.
- Невалидный ввод и исчерпание ресурсов дают различимые документированные ошибки.
  Ресурсный предел никогда не преобразуется в `null`.
- Функция синхронна, детерминирована и безопасна для повторных независимых вызовов.
  Для тяжёлых входов потребитель может вызвать её в Worker.

Пределы конкретного поиска отделены от механики. Текущая безопасная числовая
кодировка допускает N≤18; расширение кодировки сверх этого не является задачей
миграции. Нет специального ограничения N≤8 в модели библиотеки.

## Алгоритм и структура

Сохраняем точную рациональную матричную подготовку, достаточный сертификат пути,
A* с согласованной нижней оценкой и точный BFS для вырожденной матрицы.
Основная гарантия — минимум количества действий A. Разные выбранные пластины U
и единичные сдвиги C измеряются отдельно; общий минимум U/C среди равных по A
путей не обещается.

Применяем SOLID, KISS, YAGNI и DRY к текущей задаче:

- один публичный facade и одна реализация механики;
- объект модели замка отвечает за проверенный неизменяемый ввод и эффекты;
- стратегии A* и BFS имеют небольшой внутренний общий контракт;
- приоритетная очередь и бюджет поиска инкапсулируют своё состояние;
- точная арифметика и преобразования остаются чистыми функциями там, где класс
  не даёт дополнительной ответственности;
- композиция без иерархий ради ООП, DI-контейнеров, реестров и плагинной системы;
- CLI остаётся отдельным адаптером и не входит в распространяемое ядро;
- диагностические инструменты бенчмарка не расширяют публичные два аргумента.

Исходники — TypeScript в strict mode, без `any` и необоснованных подавлений
проверок. Runtime-зависимостей нет; инструменты разработки являются devDependencies.

## Четыре распространяемых файла

| Файл | Подключение |
|---|---|
| `gothic-lock-solver.mjs` | Читаемый ESM: браузер или Node.js import |
| `gothic-lock-solver.min.mjs` | Минифицированный ESM |
| `gothic-lock-solver.js` | Читаемый classic script, глобальный `GothicLockSolver.solveLock` |
| `gothic-lock-solver.min.js` | Минифицированный classic script |

Каждый файл самодостаточен: без внешних imports, дополнительных chunks, обращения
к сети, Node API и UI. Сборка использует один TypeScript entry point, форматы
ESM и IIFE. Минификация не меняет контракт, ошибки и найденный результат.
Текущий ручной ESM-assembler заменяется стандартной сборкой Vite.

Проверяется настоящая минификация обоих `.min` файлов: стандартная настройка
Vite library mode сама по себе может сохранять пробелы в ESM. Если нужен отдельный
финальный проход минификатора, он входит в нашу сборку и проверяется на выходе.

Декларации типов для ESM-путей, описание глобального API, лицензия и manifest
с версией, commit SHA и хэшами сопровождают выпуск. Это вспомогательные файлы;
для исполнения потребитель выбирает ровно один из четырёх runtime-файлов.

## Проверки реального использования

Vitest projects разделяют Node и настоящий браузер через Playwright. `jsdom`
или изолированный Node VM не считаются подтверждением браузерной совместимости.
Начальная браузерная матрица: Chromium, Firefox, WebKit.

1. Общий каталог всех 45 входов проверяется в Node и Browser Mode. Каждый путь
   независимо воспроизводится по одному делению и сверяется с точным минимумом A.
2. Малые модели и контрпримеры защищают границы, матричные ложноположительные
   выводы, вырожденность, недостижимость и повторный выбор пластины.
3. Проверяются именно собранные файлы: оба ESM в Node, все четыре варианта
   в браузерах. Для каждого проверяются 45 входов и одинаковый публичный контракт.
4. E2E загружает реальные неизменённые байты dist через HTTP, classic script
   и `script type=module`, а не повторно преобразованный dev-server исходник.
   Проверяются отсутствие дополнительных runtime-загрузок и работа Worker.
5. Отдельный небольшой сценарий проверяет classic script через `file://`;
   локальный ESM через `file://` не обещается.
6. Неподдерживаемая среда или невозможность запустить браузер явно отражаются
   в результате. Пропущенная обязательная среда не даёт статуса полной готовности.

Покрытие публикуется как диагностический отчёт. Число тестов или процент покрытия
не подменяют независимую проверку механики и производственного импорта.

## Бенчмарк и snapshot

Сохраняем текущие 45 fixtures, происхождение данных, точный baseline и сторонний
решатель на закреплённом commit. Его код читается из отдельного checkout и
проверяется хэшами; AGPL-исходник не включается в наш Apache-репозиторий.

На каждом PR сравниваются candidate и base в одной среде, с прогревом,
чередованием порядка и повторными измерениями. Исторический snapshot остаётся
доказательством прошлых измерений, но не заменяет свежее парное сравнение.
Статистики разных браузеров, Node и разных машин не смешиваются.

Для каждого замка и реализации отчёт содержит A/U/C, переключения, отдельные
замеры времени, median/p95, параметры выборки, версию среды и хэши артефактов.
Также сохраняются размер bundle и измерения памяти с точным названием метрики.

Память Node измеряется отдельным запуском в изолированном процессе: peak RSS
включает runtime и не выдаётся за точное число байтов, выделенных алгоритмом.
Для браузеров портативного точного peak-heap измерения не обещаем: значение
отмечается как недоступное либо приводится отдельно с указанием API и ограничений.
Замер памяти отделён от замера скорости, чтобы инструментация не искажала таймер.

**Правила сравнения:**

- Неверный путь, потеря решаемости, рост A относительно установленного минимума,
  несоответствие контракту или артефакту блокируют CI.
- A/U/C сверяются по каждому замку. При равном A ухудшение U/C требует явного
  обоснования и отдельного принятого изменения snapshot. Миграция в TypeScript
  сама по себе не является таким обоснованием.
- Одиночное отклонение времени/RSS на общей CI-машине не считается доказанной
  регрессией. Отчёт помечает сигнал, проверяет шум и выполняет ограниченный повтор.
- Допуски времени и памяти калибруются на сравнении неизменённой версии с собой
  до включения performance verdict. Они не выбираются ради зелёного результата.
- Детерминированные ресурсные лимиты — строгая проверка. Измеряемые время/RSS —
  отдельный performance verdict с оценкой достоверности, видимый в PR.
- Snapshot не перезаписывается автоматически тестами. Его обновление — отдельная
  команда и проверяемый diff с источником, причиной и результатами сравнения.
- Для сравнения используется baseline целевой ветки PR, чтобы candidate не мог
  скрыть ухудшение простым изменением собственного ожидаемого файла.

## CI и публикация

PR запускает lint, typecheck, unit/integration, сборку, тесты dist/E2E и сравнение
бенчмарка. JSON/Markdown, покрытие и четыре файла доступны как CI artifacts.
Документируется одна команда локальной полной проверки и отдельные команды этапов.
PR не публикует боевой `latest` и не получает права деплоя.

После будущего слияния в `main` workflow повторно подтверждает проверки точного
merge commit и публикует проверенные байты на GitHub Pages. Публикация не требует
npm и не добавляет сборку потребителю. Предлагаемый адрес имеет вид
`https://marcus-rise.github.io/gothic-lock-solver/releases/<commit-sha>/<file>`.
Это планируемый URL, сейчас он не является опубликованным продуктом.

Релизы по commit SHA сохраняются при следующих deployments. Отдельная ветка
публикации может хранить накопленный статический дистрибутив; source-ветка хранит
TypeScript, конфигурацию и принятые benchmark snapshots. `latest` допустим для
демонстраций; интеграции закрепляют commit или неизменяемую версию.

После публикации проверяются реальные URL: MIME JavaScript для `.mjs`, CORS
для импорта с другого origin, SHA256 и поведение одного известного замка.
Если GitHub Pages в этом окружении не удовлетворяет условиям, это фиксируется
до объявления CDN-контракта готовым. Обычная GitHub blob-ссылка не является
ссылкой на исполняемый файл. GitHub Release с файлами может служить архивом выпуска.
